How 5,000 text descriptions turn into a 2D matrix of shape (5000, 384), and why this powers millisecond searches.

1. Single String vs. Full Dataset

In the last lesson you created an embedding for one string. Now you are stacking all 5,000 movie embeddings into a single cohesive structure.

Single Query Embedding shape: (384,)

"teddy bear" → 1D Vector (Rank 1 Tensor)

-0.019

A single list of 384 floating-point coordinates pointing in semantic space.

Document Embeddings Store shape: (5000, 384)

All 5,000 Movies → 2D Matrix (Table of Numbers)

[ [-0.062, 0.054, ... -0.019], # Movie 0
[ 0.018, -0.091, ... 0.043], # Movie 1
... (4998 more rows) ...
[-0.041, 0.033, ... 0.007] ] # Movie 4999

5,000 rows stacked vertically, each row having 384 columns.

💡
In Python: embeddings.shape[0] == 5000 (number of documents/rows), while embeddings.shape[1] == 384 (number of dimensions/features per vector).

3. Why NumPy & The .npy File Format?

Storing 5,000 vectors as plain JSON or text would be tens of megabytes and slow to parse. Here is what NumPy does:

5,000 × 384
Matrix Dimensions
1,920,000
Total Float Values
~7.68 MB
Binary Size on Disk
< 5 ms
Load Time with np.load()
# In your code: import numpy as np # Fast binary write: raw memory dump of IEEE 754 floats np.save("cache/movie_embeddings.npy", self.embeddings) # Instant load on application startup (memory-mapped ready) self.embeddings = np.load("cache/movie_embeddings.npy")
