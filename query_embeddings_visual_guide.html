Query Embeddings & Vector Space Alignment

Why we cannot compare string queries directly to document matrices, and how SentenceTransformer projects search intents into the exact same 384-dimensional embedding manifold.

1. The Coordinate Alignment Problem

In BM25 keyword search, queries and documents are compared by matching surface-level tokens. In semantic search, 5,000 documents already exist as 5,000 vectors in $\mathbb{R}^{384}$. A raw string cannot be mathematically multiplied with a vector matrix until it is projected into that exact same coordinate space.

Why "FUNNY bear MOVIES" and "funny bear movies" produce identical vectors: Modern transformer models like all-MiniLM-L6-v2 are token-level neural networks that normalize casing and recognize semantics beyond surface characters. No custom lowercasing or stemming regex is required—just basic whitespace validation.

3. Assignment Implementation Blueprint

The assignment requires wiring two specific layers together: the core library helper and the CLI command parser.

1
In cli/lib/semantic_search.py

Create the high-level helper function embed_query_text(query): 

def embed_query_text(query: str):
    search = SemanticSearch()
    embedding = search.generate_embedding(query)
    print(f"Query: {query}")
    print(f"First 3 dimensions: {embedding[:3]}")
    print(f"Shape: {embedding.shape}")
  • Reuses existing generate_embedding()
  • Empty queries are rejected automatically
  • Exact stdout format expected by Boot.dev test suite
2
In cli/semantic_search_cli.py

Add the CLI subcommand embed_query using argparse: 

# 1. Import helper
from lib.semantic_search import embed_query_text

# 2. Register subparser
embed_query_parser = subparsers.add_parser(
    "embed_query", help="Embed search query"
)
embed_query_parser.add_argument(
    "query", type=str, help="Query string"
)

# 3. Handle command match
case "embed_query":
    embed_query_text(args.query)
